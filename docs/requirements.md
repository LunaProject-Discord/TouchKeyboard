# 要件定義

## 1. 背景

Windows 11 のタッチキーボードには「標準 / 50音 / テンキー / コンパクト / 分割 / クラシック」のレイアウトがあるが、Microsoft IME がアクティブなときにしか選択できない。ATOK を使用中は既定レイアウトに固定される。

原因は OS の仕様である（詳細は `technical-notes.md`）。IME 側でしか解決できず、利用者側の設定や回避策では対処できない。

一方で ATOK の入力ミス補正は手放せない。タッチ入力は打鍵ミスが出やすく、大画面タブレットではこの補正の価値が最も大きい。

したがって、両立させるにはタッチキーボードを自作する以外の手段がない。

## 2. 目的

Windows タブレットにおいて、ATOK（および任意の IME）の変換・補正機能をそのまま活かしながら、ハードウェアキーボード相当のキー配列をタッチ操作で利用できるようにする。

## 3. 想定利用シーン

通常の Windows タブレットとしての日常利用。文章入力、ブラウジング、アプリケーション操作。特定業務用途に限定しない。

## 4. スコープ

### 対象に含む

- 通常のデスクトップアプリケーションへのタッチ入力
- 日本語配列（JIS）のフルレイアウト
- 画面下部へのドッキングと自動表示

### 対象に含まない

- UAC のセキュアデスクトップ、サインイン画面での入力（自作アプリでは原理的に不可。この場面は OS 標準のタッチキーボードに委ねる）
- 手書き入力、絵文字パネル、音声入力
- 英語配列その他の言語レイアウト
- 予測変換 UI の独自実装（IME が表示するものをそのまま使う）
- OS 標準タッチキーボードの置き換え・登録（あくまで独立したアプリケーションとして動作する）

## 5. 絶対制約

以下に反する実装は、目的を達成できないため受け入れない。

| 項目 | 要件 | 理由 |
|---|---|---|
| キー送出 | `SendInput` + `INPUT_KEYBOARD` + `KEYEVENTF_SCANCODE` のみ | 通常のキーボードと同じ入力経路を通さないと IME が介入せず、ATOK の補正が働かない |
| ウィンドウスタイル | `WS_EX_NOACTIVATE \| WS_EX_TOOLWINDOW` | タップのたびに入力先のフォーカスが外れるのを防ぐ |
| 画面領域の確保 | `SHAppBarMessage`（`ABM_NEW` → `ABM_SETPOS`） | Topmost で覆う実装では入力欄が隠れる |
| キー配列の保持 | データとして外部化 | XAML への直書きは配列変更・レイアウト追加を不可能にする |

## 6. 機能要件

### F-1 キー入力

- タップしたキーのスキャンコードを送出する
- 拡張キー（矢印、Insert/Delete/Home/End/PageUp/PageDown、右 Ctrl、右 Alt など）は `KEYEVENTF_EXTENDEDKEY` を併用する
- 長押しでキーリピートする。開始遅延と間隔は設定可能とする
- キーダウンとキーアップを対で送出し、押しっぱなしを残さない
- アプリケーションの異常終了時に修飾キーが押されたまま残らないよう配慮する

### F-2 修飾キーのラッチ

- Shift / Ctrl / Alt / Win / Fn はタップでラッチし、次の通常キー入力まで保持する
- 複数の修飾キーを同時にラッチできる
- ダブルタップでロックし、明示的に解除するまで保持する
- ラッチ状態とロック状態を視覚的に区別できる
- **指で押さえている間は保持する。** 押さえたまま別の指で複数の文字を打てる（マルチタッチ）
  - ラッチは 1 文字で消費されるため、押さえ続けだけでは足りない
  - 押さえて何も打たずに離した場合はタップとして扱う
  - ロック中に押さえた場合、離してもロックは維持する

### F-3 レイアウト

- JIS 配列のフルレイアウトを持つ
- 最上段に Esc および F1〜F12 を含む
- 日本語入力に必要なキーを含む: 半角/全角、無変換、変換、カタカナ/ひらがな、`\_`、`¥|`
- 矢印キーを含む
- レイアウト定義は外部ファイルから読み込む（キーの位置・サイズ・ラベル・スキャンコード・拡張キーフラグ）
- 将来のレイアウト追加（テンキー付き、コンパクト等）を妨げない構造とする

### F-4 表示と配置

- 画面下部にドッキングし、他ウィンドウの作業領域を圧迫しない
- 高さをドラッグで変更でき、変更後も AppBar の確保領域が追従する
- 高さと表示状態を次回起動時に復元する
- 常に最前面に表示する
- 上端のグリップで操作を分ける
  - 押さえたまま（350ms）ドラッグ: 高さ変更
  - 押してすぐ下へ払う: 非表示
  - 上へのドラッグや短いタップ: 何もしない

### F-5 自動表示

- テキスト入力可能な要素にフォーカスが移ったとき自動表示する
- 読み取り専用の要素では表示しない（ブラウザで閲覧中など）
- 入力対象から外れたとき自動的に隠す
- サジェストや変換候補が出ても隠さない（呼び出し元に所有された補助ウィンドウは入力の続きとみなす）
- 物理キーボードが使える状態では自動表示しない
  - 装着されたとき、および物理キーボードで打鍵されたときは隠す
  - 外されたときは、その時点で入力欄にフォーカスがあれば表示する
- 自動表示のオン／オフを設定で切り替えられる
- 手動での表示／非表示手段を持つ

### F-6 常駐

- タスクトレイに常駐し、そこから表示切替と終了ができる
- Windows 起動時の自動起動を設定で切り替えられる

## 7. 非機能要件

| 項目 | 要件 |
|---|---|
| DPI | Per-Monitor DPI Awareness V2 に対応する。モニタ間移動およびスケーリング変更時にレイアウトとドッキング位置が破綻しないこと |
| マルチモニタ | ドッキング先モニタを選択でき、モニタ構成変更時に復帰できること |
| 応答性 | タップから入力反映までの遅延が体感できないこと |
| フォーカス | いかなる操作でも入力先アプリケーションのフォーカスを奪わないこと |
| 保守性 | ネイティブ宣言は `Interop/` 配下に集約すること |

## 8. 技術スタック

- C# / **WinUI 3（Windows App SDK）** / .NET 10
- UI Automation（自動表示の判定に使用）

.NET Framework ではなく .NET を選ぶ理由は Per-Monitor DPI V2 のサポートが十分であること。タブレットで外部ディスプレイに接続する運用があるため、ここは妥協しない。

### WPF から WinUI 3 へ移行した理由

当初は WPF で実装し、Phase 3 まで完成させた。移行の決め手は Acrylic である。

WPF では DWM のシステムバックドロップが**非アクティブなウィンドウで単色にフォールバック**する。絶対制約により本アプリは `WS_EX_NOACTIVATE` で構造上つねに非アクティブなため、この経路が使えず、非公開 API の `SetWindowCompositionAttribute` に頼る必要があった。

WinUI 3 では `DesktopAcrylicController` の `SystemBackdropConfiguration.IsInputActive` を `true` に固定することで、**公開 API のみで**同じ結果が得られる（詳細は `technical-notes.md`）。

副次的な利点として、Fluent の外観が標準で得られること、タッチとマウスが `Pointer` に統一され WPF で必要だった昇格抑止が不要になることがある。

**代償**: Windows App SDK ランタイムへの依存。未導入の環境では自己完結配置となり約 240MB になる。また WinUI 3 には標準の通知領域アイコンが無く、`Shell_NotifyIcon` を直接扱う必要がある。

移行にあたり、`Interop/` `Input/` `Layout/` `Settings/` は変更なしで流用できた。UI フレームワークに依存させない設計が効いている。

## 9. 既知の制限

### 起動には署名と配置場所の条件がある

マニフェストで `uiAccess="true"` を指定している。支援技術のための権限で、スクリーンキーボードは Windows が想定している用途にあたる。これにより 2 つの制限が外れる。

- **シェルより上の Z 順バンドに入る。** タスクバーやスタートメニューの下に潜らない。これが無いと、スタートメニューを開いた時点でキーボードが隠れて使えない
- **UIPI を越えて昇格アプリへ入力できる。** タスクマネージャ、regedit など

代償として、次の両方を満たさないと**起動そのものに失敗する**。

- 実行ファイルが Authenticode 署名済みであること
- `Program Files` 配下など、信頼された場所から起動されること

このためビルド結果を直接実行できない。開発中は `tools/install-dev.ps1` が署名と配置を行う。最終版ではインストーラーに移す（`open-questions.md`）。

### スキャンコードの解釈は OS のキーボードレイアウトに依存する

日本語配列固有キーが意図どおり解釈されるのは、OS のキーボードドライバが日本語 106/109（`kbd106.dll`）の場合のみ。英語配列として認識されている環境では別の文字になる。

確認方法は `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\i8042prt\Parameters` の `LayerDriver JPN`。

### AppBar の残骸は後から掃除できない

他プロセスが登録した AppBar を外部から解除する API は存在しない。異常終了で確保領域が残った場合、アプリ側では回復できない（Explorer の再起動が必要）。`ABM_REMOVE` を確実に通す経路を三重化して対処する。

### その他

- UWP / ストアアプリでは UI Automation の情報の取り方が異なり、自動表示の判定が不安定になる可能性がある
- セキュアデスクトップでは動作しない
- OS 標準のタッチキーボードの自動表示は無効化しておく必要がある（タスクバーからアイコンを非表示、または `EnableDesktopModeAutoInvoke` を 0）
